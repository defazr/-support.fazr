## 10. 공통 핵심 요약 박스 수정 옵션

현재 문제:
updates/[slug]/page.tsx의 핵심 요약 박스가 공통 하드코딩이며, 12개 업데이트 글 전체에 동일 노출된다.
문구 중 "추경 국회 통과 4월 10일"은 5/18 이후 stale 위험이 있다.

### 옵션 A. 글 발행일 기준 박스

내용: 각 글의 date 값을 읽어 발행일 기준 안내 문구를 표시한다.

장점:
- 각 글이 발행 당시 기준이라는 점이 명확해짐
- 속보형 업데이트 글과 잘 맞음

단점:
- 공통 박스 안의 실제 내용은 여전히 글별로 달라야 자연스러움
- date만 바꾼다고 모든 글의 핵심 요약이 정확해지는 것은 아님

구조 변경 범위: 작음~중간

### 옵션 B. updates.ts에 summaryBox 필드 추가

내용: 각 업데이트 글 데이터에 summaryBox 또는 highlights 필드를 추가해 글별 핵심 요약을 따로 관리한다.

장점:
- 가장 정확함
- 글별 문맥과 발행일 기준을 모두 반영 가능
- 장기적으로 안전함

단점:
- 기존 12개 글에 데이터 필드 추가 필요
- QA 범위가 커짐
- 5/17 D-Day 전환 작업에는 부담이 될 수 있음

구조 변경 범위: 중간

### 옵션 C. 정책 일정 기준 공통 박스로 통일 (추천)

내용: 공통 박스를 글별 뉴스 요약이 아니라 정책 일정 안내 박스로 바꾼다.

예:
- 2차 신청: 2026년 5월 18일 09:00 ~ 7월 3일 18:00
- 첫 주 요일제: 5월 18일 ~ 5월 22일
- 이의신청: 2026년 5월 18일 09:00 ~ 7월 17일 18:00
- 사용기한: 2026년 8월 31일까지
- 문의: 1670-2626, 국민콜 110

장점:
- 12개 글 전체에 동일 노출되어도 의미가 맞음
- stale 위험이 가장 작음
- 구조 변경 범위가 가장 작음
- 5/17 작업에 적합

단점:
- 글별 맞춤 요약은 아님

구조 변경 범위: 가장 작음

### 추천 기준

5/17 D-Day 전환에서는 옵션 C를 우선 추천한다.

## 11. 색인 요청 시점 룰

Q&A 글 발행 후 색인 요청은 반드시 라이브 반영 확인 후 진행한다.

### 색인 요청 전 필수 조건

1. Vercel 배포 완료
2. 신규 URL curl 200 확인
3. 신규 글 HTML에서 핵심 문구 확인
4. sitemap.xml에 신규 URL 포함 확인
5. canonical이 정상 URL로 출력되는지 확인
6. Article JSON-LD 유지 확인
7. FAQPage schema를 추가했다면 JSON-LD 출력 확인

### 색인 요청 전 검증 예시

```bash
curl -I https://support.fazr.co.kr/updates/objection-qa-2026

curl -s https://support.fazr.co.kr/sitemap.xml | grep "objection-qa-2026"

curl -s https://support.fazr.co.kr/updates/objection-qa-2026 | grep -oE "이의신청|보험료 초과|국민신문고|1670-2626|7월 17일" | sort | uniq
```

### 시간 기준

- 5/17 밤에 배포가 끝나고 sitemap 반영까지 확인되면 5/17 밤 색인 요청 가능
- 5/17 23:00 이후 배포되거나 sitemap 반영이 불확실하면 색인 요청은 5/18 09:00 이후로 이월
- 5/18 새벽에 sitemap 미반영이 보여도 코드 수정 금지
- 5/18에는 색인 요청, 모니터링, 지식인 답변만 진행
- GSC 유효성 검사 재실행 금지
